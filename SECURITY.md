# Security reporting

**Do not disclose an exploitable vulnerability in a public issue or pull request.**

Use [Report a vulnerability](https://github.com/GuardLatice/.github/security/advisories/new) for a private report to the organization maintainers. For another GuardLatice repository, prefer its own private reporting route when enabled; otherwise use this central route and identify the affected component.

Include the affected version or commit, prerequisites, a minimal reproduction using synthetic data, expected and observed behavior, and impact. Do not include live credentials, private keys, customer data or unnecessary personal information.

Test only systems you own or are explicitly authorized to test. This policy does not authorize scanning or attacking production systems and does not establish a bounty program.

Supported versions and response commitments are defined per released product or contract. Experimental artifacts are not automatically production-supported. Coordinate public disclosure with maintainers.
